# Терминальный анализатор и очистка диска — дизайн

Статус: основа утверждена пользователем 2026-10-30; учтены замечания ревью, английский интерфейс и упрощённая навигация по текущему каталогу. MVP реализован; результаты проверок и ограничения выпуска описаны в [отчёте проверки](validation.md).

Отложенный вариант с раскрываемым деревом описан в [отдельном документе](future/tree-navigation.md) и не входит в MVP.

## Замысел

Открытая утилита для macOS помогает понять, какие доступные пользователю файлы и папки занимают место, вручную выбрать ненужное и удалить его после проверки. Она автоматизирует привычный сценарий `ls` → `du` → `rm` в удобном терминальном интерфейсе. Ориентир по взаимодействию — `mo analyze` из Mole; копировать его код или набор функций не планируется.

Пользователи — владельцы Mac, которым нужен контроль над очисткой без автоматических рекомендаций. Утилита распространяется с исходным кодом под **GPL-3.0-only**.

## Границы первой версии

- Полноэкранный список непосредственных элементов текущего каталога с навигацией стрелками, переходом в папку и на уровень выше, отметкой нескольких объектов, экраном исключений, настройками и отдельным тестовым прогоном. Текущий каталог всегда является корнем анализа; раскрытых ветвей и отдельной команды выбора корня анализа нет.
- Пользовательский интерфейс — на английском языке, включая экраны, подсказки, предупреждения, подтверждения, статусы и сообщения об ошибках; исключение — вариант `Русский` в переключателе `Answer language` и сгенерированный ответ, язык которого выбирается пользователем. Имена файлов и пути сохраняются с безопасным экранированием при отображении; диагностический вывод системных команд может сохранять язык источника.
- Начальный каталог — `~`. Пользователь может выбрать другой доступный каталог, в том числе на внешнем томе. `r` открывает пустое поле пути; пользователь вставляет или вводит абсолютный путь, `~`/`~/` либо путь относительно текущего каталога и нажимает Enter. Подсказка `r path` видна в браузере при любой ширине. Сначала проверяется буквальный путь; если такой каталог не открыт, совпадающая пара внешних кавычек и один завершающий перевод строки из скопированного пути обрабатываются как запасной вариант; пробелы, Unicode и разделители каталогов сохраняются. `Ctrl+U` очищает поле. Многострочный и неверный ввод отклоняется; при ошибке каталог и состояние браузера не меняются. Ввод, вставка и ошибки пути сохраняют текущее состояние браузера; успешное открытие каталога сбрасывает отметки и фильтр имён, как обычная навигация, но не меняет общий список исключений. Путь символической ссылки на каталог разрешается в фактический каталог до анализа.
- В браузере и оценках очистки показан объём занятого места, а не логический размер; AI-объяснение отдельно получает логический и выделенный размеры с явными подписями. Для Корзины показывается размер выбранного, для окончательного удаления — оценка освобождаемого места; точные подписи приведены в разделе «Тексты интерфейса». APFS-клоны, жёсткие ссылки, снимки и другие особенности файловой системы могут изменить фактический результат. Обе величины — оценки из последнего анализа; неполнота и неизвестный размер отмечаются явно. Успешная операция не выдаёт оценку за фактически освобождённый объём.
- Удаляются только объекты, вручную отмеченные пользователем. Автоматический поиск «мусора», удаление приложений с остатками, системное обслуживание и очистка Корзины не входят в первую версию.
- Тестовый прогон — отдельная команда по желанию. Он перечисляет пути внутри выбранных папок, показывает оценку из последнего результата `du` и ничего не меняет. Реальное действие всегда имеет отдельный экран подтверждения с путями, режимом и оценкой объёма.
- Режим действия выбирается в настройках: Корзина либо окончательное удаление. По умолчанию — Корзина. Если перемещение в Корзину не удалось, приложение не заменяет его окончательным удалением.
- Исключения составляют один общий список для всех выбранных каталогов и дисков и сохраняются между запусками. Маски совпадают с именами потомков выбранного корня на любой глубине; имя самого корня и его предков не проверяется. Изменение списка в любом месте меняет общий список; локальных списков, переопределений и наследования нет. При загрузке прежние списки для отдельных корней объединяются без точных дублей, чтобы сохранить настройки; загрузка не меняет файл, последующее обычное сохранение записывает общий список. Добавление и удаление масок сохраняется автоматически; ошибка сохранения показывается пользователю и не выдаётся за успешную запись. При неуспехе сохранения изменённые правила остаются активны в текущем запуске, но их сохранность после выхода не гарантируется.
- **Объяснение через Codex:** клавиша `i` для элемента под курсором открывает подтверждение с его путём и явным описанием доступа для чтения до запуска. Отметка элемента и предварительный анализ не нужны. Установленный авторизованный Codex CLI запускает `codex exec` с разрешениями команд только для чтения. CLI может читать содержимое файлов и файлы за пределами выбранного пути, а также передавать эту информацию Codex. Эти разрешения ограничивают локальные команды, но не гарантируют полной изоляции от всех возможностей Codex. Сам DiskCleaner не меняет отметки и не запускает очистку при объяснении. Для авторизованного CLI отдельный API key не требуется. Это не переход в окно Codex Desktop. В подтверждении есть настройка `Answer language: English` (по умолчанию) / `Русский`; Left/Right или Tab меняет и сразу сохраняет выбор. Настройка влияет только на язык ответа: инструкции Codex всегда на английском, новых файловых метаданных она не добавляет. По Enter запускается асинхронный запрос; ответ открывается на прокручиваемом экране. Esc до запуска возвращает в браузер; во время запроса отменяет работу и ждёт её завершения перед возвратом. Ошибки показываются как диагностика.

Для запуска используется установленный CLI: сначала поиск `codex` в `PATH`, затем проверенные пути внутри ChatGPT.app. Авторизация берётся из CLI, пользовательские настройки и правила CLI не загружаются. Начальный JSON-контекст передаётся через stdin и содержит путь, имя, тип, время изменения, признак владения текущим пользователем, для символической ссылки — сохранённый текст её цели (без перехода по ней), режим удаления из настроек (`delete_mode`), число непосредственных элементов (не более 10 000, иначе помечается как нижняя граница), не более 32 их имён с типами и два отдельных размера записи: логический (`entry_logical_size_bytes`) и выделенный на диске (`entry_allocated_size_bytes`). Если текущий каталог просканирован, `last_scan` передаёт результат последнего скана этого элемента: выделенный размер с содержимым, состояние (`complete`, `partial`, `unknown`, `skipped` с причиной) и время скана; это снимок, а не текущее измерение. Без результата скана поле равно `null`. Для обычного файла объяснение в первую очередь использует выделенный размер, а логический указывает отдельно; это помогает объяснить разницу у sparse-файлов. `GB` — 1 000 000 000 байт, `GiB` — 1 073 741 824 байта. Неизвестное выделенное значение передаётся как `null`, а не как ноль. Размеры записи каталога относятся только к самой записи, не к его содержимому; размер содержимого берётся только из `last_scan`. Размер выделения не обещает объём места, который освободится: на результат влияют APFS-клоны, снимки, сжатие и жёсткие ссылки. Сборщик не обходит подкаталоги, не следует по ссылкам и не читает содержимое файлов. После этого Codex может просматривать файлы с разрешениями команд только для чтения. Запрос ограничен двумя минутами; stdout ограничен 1 MiB, stderr — 64 KiB, итоговый ответ — 64 KiB. CLI запускается из временного нейтрального каталога и использует JSON-протокол. Некоторые возможности отключаются параметрами поддерживаемого CLI; это не гарантия полной изоляции от всех инструментов или конфигурации уровня системы/организации. Ошибки входа, лимитов учётной записи и несовместимой версии CLI показываются понятными сообщениями. Ответ и сырые журналы CLI не сохраняются как кэш.

Язык ответа хранится в настройках приложения как `explain_language` (`en` или `ru`); отсутствующее значение означает английский. Ввод запроса всегда остаётся английским; выбранная опция задаёт язык только результата и сохраняется сразу. Она не добавляет метаданные к запросу. Ответ — простой текст без Markdown, не длиннее примерно 150 слов, в виде строк с метками: риск и уверенность, что это, размер, последствия удаления, что не проверено и, при наличии, более безопасная альтернатива без команд. Шкала риска задана в шаблоне: `low` — пересоздаваемые данные, `moderate` — потеря настроек или состояния, `high` — возможно уникальные данные, облачная синхронизация, ключи или необходимое для работы, `unknown` — недостаточно данных. Инструкции просят ограничиться несколькими быстрыми командами метаданных без рекурсивных обходов, чтобы уложиться в лимит времени. Ответ объясняет назначение объекта, вероятные риски и последствия удаления, возможность восстановления и степень уверенности; неизвестное обозначается как неизвестное, предположения не выдаются за факты. Объяснение не разрешает удаление и не запускает очистку.

Базовый английский шаблон и выбор языка ответа находятся в [internal/explain/prompt.go](../internal/explain/prompt.go). [explain.go](../internal/explain/explain.go) собирает инструкции и JSON, [metadata.go](../internal/explain/metadata.go) формирует метаданные, а [cli.go](../internal/explain/cli.go) передаёт запрос через stdin в `codex exec`. Полный шаблон здесь не дублируется.

## Тексты интерфейса

Этот раздел — единственный источник точных подписей размера и статусов результата. Подписи размера используются в выборе, тестовом прогоне и подтверждении; состояние неполноты или неизвестного размера показывается рядом.

| Контекст | Текст | Значение |
| --- | --- | --- |
| Режим Корзины | `Selected size` | Оценка занятого места выбранными объектами |
| Окончательное удаление | `Estimated space to reclaim` | Оценка, а не обещание фактического освобождения |
| Тесная шапка браузера, Корзина | `Selected:` | Сокращённая подпись того же выбранного объёма |
| Тесная шапка браузера, окончательное удаление | `Est. reclaim:` | Сокращённая подпись той же оценки освобождения |
| Операция выполнена | `Completed` | Команда завершилась успешно |
| Операция пропущена | `Skipped` | Действие для объекта не запускалось; рядом показывается причина |
| Ошибка действия | `Failed — changes may have occurred` | Исполнитель вернул ошибку; часть содержимого могла измениться |

## Цвета и справка

Пустой список исключений обозначается красным текстом `No exclusions` (в редакторе — `No exclusions (optional)`); это подсказка, а не запрет анализа. Голубой выделяет заголовки, приглушённый серо-синий фон — строку под курсором, флажок `[x]` — отмеченные объекты. Отметка `[x]` остаётся видна независимо от цвета строки. Цвет предупреждения сохраняется на строке под курсором; зелёный — отмеченные объекты, наличие исключений и успешные результаты, жёлтый — исключённые элементы, неполные или неизвестные размеры. Красным показываются предупреждение о восстановленных размерах и только подпись `Complete` в колонке `Status` для восстановленного полного измерения. Строка сохраняет обычную окраску курсора и выбора; метка `[x]` по-прежнему указывает на выбор. Предупреждения об окончательном удалении и ошибки выполнения очистки также показываются красным. Подписи и маркеры сохраняют смысл без цвета; `NO_COLOR=1` отключает оформление. Цветовые коды не влияют на переносы строк и прокрутку.

Клавиши `?` и `h` открывают справку из шести тем: начало работы, просмотр файлов, анализ и размеры, исключения, очистка, отображение и клавиши. Left/Right или Tab переключает тему, `1–6` открывает её напрямую; Up/Down и PgUp/PgDn прокручивают текст, Home/End переходят к началу/концу темы. Из редактора исключений, подтверждения анализа и экранов очистки сразу открывается соответствующая тема. Esc, `?` или `h` возвращает к предыдущему экрану и позиции прокрутки без изменения выбора или подтверждения. В полях ввода пути, масок и фильтра эти символы вводятся как текст; во время выполнения операции доступна только отмена. На основном экране всегда есть подсказка `? help`.

## Сценарий анализа

Список по умолчанию отсортирован по алфавиту без учёта регистра; при равенстве используется исходное имя. Клавиша `t` в списке переключает алфавитную сортировку и сортировку по размеру от большего к меньшему и перемещает курсор на первый видимый элемент. Отметки и текущий снимок анализа сохраняются; повторное сканирование не запускается. Текущий режим показан над списком при наличии места; подсказка `t` может опускаться в тесном окне, но остаётся в справке. Равные размеры упорядочиваются по алфавиту; элементы без измеренного размера и исключённые элементы идут после измеренных. Частичные измерения участвуют по доступному числовому значению с сохранением отметки `Partial`. До анализа и после сброса размеров режим показывает `Size (scan needed)` и использует алфавитный порядок. После успешного анализа сортировка по размеру применяется автоматически. Автоматическая сортировка при анализе, восстановлении кэша и навигации сохраняет установленное поведение истории курсора. Режим сохраняется при навигации в текущем запуске, но новый запуск всегда начинается с алфавитного порядка.

1. При запуске первым экраном всегда открывается просмотр файловой системы: текущий путь `~` (либо каталог из `-root`) и список его непосредственных элементов без размеров, включая скрытые. Редактор исключений автоматически не открывается; настройка исключений необязательна. `↑/↓` или `k/j` перемещают выделение на один видимый элемент, PgUp/PgDn — на один экран, Home/End — к первому/последнему видимому элементу. `Enter` или `→` переводят внутрь выделенной папки, `←` — в родительскую, `r` открывает ввод пути, в том числе к внешнему тому. Переход заменяет список содержимым нового каталога; он же становится корнем анализа. Для каждого посещённого канонического корня в памяти сохраняется путь под курсором, а не индекс: возврат восстанавливает его после перечитывания списка и сортировки. Исчезнувший или скрытый элемент заменяется первым видимым. При прямом переходе к родителю выделяется папка, из которой вышли, даже если приложение запущено внутри неё и родитель ещё не посещался. Ошибочный переход не меняет историю; новый запуск её не восстанавливает. Внутреннее перечитывание того же корня без перехода в другой сохраняет прежнее поведение: первый видимый элемент, а не восстановление истории. В корне файловой системы `←` ничего не меняет. Переходы читают только непосредственные элементы и не запускают `du`.
2. Клавиша `s` открывает подтверждение и очищает прежнее уведомление браузера, например о сохранении исключения. Перед обходом показывается сообщение, что анализ может занять много времени; новые сообщения об ошибке или отмене анализа не скрываются. Если общий список исключений пуст, интерфейс предлагает отметить папки для пропуска. Сканирование начинается только по команде `Start scan`; пустой список исключений допустим.
3. Во время работы `du` интерфейс показывает экран с текущим путём, прошедшим временем и количеством обработанных непосредственных элементов из общего числа, включая пропущенные. Процент и прогноз времени не показываются, поскольку стоимость обработки элементов различается. Доступна отмена; навигация и изменение контекста анализа заблокированы. Результат становится доступен после завершения команды; обновление размеров в реальном времени не требуется.
4. После успешного анализа список и размеры заменяются одним снимком непосредственных элементов. При применении результата список заново не перечитывается: элемент, исчезнувший или изменившийся после чтения списка сканирования, остаётся строкой с размером `Unknown`; свежий список при следующем переходе или анализе убирает исчезнувшие имена и обновляет типы. Курсор сохраняет прежний путь, если он остался в списке, иначе ограничивается границами нового списка. Становится доступна ручная отметка для удаления. При ошибке или отмене повторного анализа прежний список непосредственных элементов сохраняется без размеров и отметок, кэш этого каталога удаляется, частичный результат не публикуется; отмена проверяется и для пустого каталога, и перед применением итогового результата. Успешный переход в другой каталог, включая возврат к родителю и ввод пути, сбрасывает отметки и текстовый фильтр, но не кэш сканирования. Список непосредственных элементов перечитывается; для совпавших неизменённых элементов восстанавливаются размеры последнего успешного сканирования, новые, изменённые или заменённые элементы остаются с неизвестным размером до сканирования. При возврате курсор следует за сохранённым для этого каталога видимым путём. `s` явно обновляет только снимок текущего каталога; снимки остальных папок не изменяются. Смена каталога не измеряет содержимое повторно. Изменение общего списка исключений очищает все сохранённые результаты сканирования. Ошибка перехода показывает причину и сохраняет прежний каталог и его состояние.
5. Для полностью недоступного каталога показывается `Size unknown`; для частично прочитанного — измеренный объём с отметкой неполноты. Ошибки доступа и отсутствие записи в выводе `du` не превращаются в нулевой размер.

Имена и типы непосредственных элементов читаются через Go `os.ReadDir`/`os.Lstat`: это эквивалент шага `ls`, который сохраняет точные имена файлов, включая перевод строки. Для каждого непосредственного элемента выбранного корня приложение запускает системную `/usr/bin/du` с `-s -x -P -B 512` и повторяющимися `-I <маска>`. Для дочернего процесса явно задаётся `BLOCKSIZE=512`, заменяя унаследованное значение: флаг `-B 512` сам по себе не фиксирует единицы вывода. Также задаётся `LC_ALL=en_US.UTF-8`, чтобы маски `du` и проверки удаления одинаково считали Unicode-символы независимо от локали терминала. `?` соответствует одной кодовой точке Unicode; составной видимый символ может включать несколько кодовых точек. Сравнение масок с именами, как и в `du -I`, учитывает регистр и не нормализует Unicode: по-разному нормализованные написания одного видимого имени (например, перенесённые с HFS+ или из архива) считаются разными именами. Окружение родительского процесса не меняется. Число из вывода умножается на 512 для получения байтов. Из вывода берётся только число до первого табулятора; путь из текста `du` не разбирается и не используется для удаления. Маски `-I` применяются к именам файлов и папок на любой глубине внутри выбранного корня: например, `cache` пропустит все одноимённые элементы, а не конкретный путь. Интерфейс прямо показывает эту область действия. Поддерживаемые маски первой версии — буквальные имена, `*` и `?` без разделителя `/`; одинаковая семантика проверяется для сканирования и защиты удаления. Размеры разных непосредственных элементов подсчитываются отдельными вызовами `du`, поэтому жёсткие ссылки между ними могут завысить сумму. Сканирование измеряет только непосредственные элементы текущего каталога (их `du`-размеры включают вложенное содержимое); чтобы получить отдельные размеры внутренних папок, нужно открыть и просканировать их. При ошибке `du` имеющийся числовой результат помечается неполным, отсутствие результата — неизвестным. При формировании непосредственного списка объект, исчезнувший между `ReadDir` и `Lstat`, пропускается только при `ENOENT`; прочие ошибки чтения метаданных завершают анализ с ошибкой. Символьные ссылки не обходятся; дочерняя точка монтирования другого тома пропускается до вызова `du`, а пользователь может выбрать её новым корнем. Успешные снимки размеров сохраняются в приватной SQLite-базе схемы 1 `scan-cache.sqlite` рядом с `config.json` в каталоге поддержки приложения; снимок содержит отдельные копии списка и карты измерений, не зависящие от сортировки браузера. При запуске приложения и возврате сначала перечитывается непосредственный список. До запуска измерения фиксируются метаданные корня и непосредственных элементов; при применении результата они проверяются повторно. Корень должен остаться тем же объектом по `os.SameFile`, иначе результат отбрасывается; у каждого элемента должны совпасть путь, тип, идентичность `Lstat`, время изменения и размер. Изменённые или заменённые во время анализа элементы получают `Unknown`, снимок помечается неполным. Только для совпавших записей сохраняется измерение. При навигационном перечитывании исчезнувшие записи убираются; новые, изменённые и заменённые получают `Unknown`; отброшенные измерения не восстанавливаются при следующем посещении. Сохранённые результаты переживают перезапуск и восстанавливаются только при совпадении метаданных; они могут устареть, если вложенные изменения не обновили метаданные непосредственной папки. Красное предупреждение включает время последнего успешного сканирования; на узком экране оно сокращено, полный текст с `s` для повторного анализа доступен через `v`. Это время измерения, а не момент проверки файлов. Это проверка метаданных непосредственных объектов, а не глубокое наблюдение за деревом: вложенные изменения могут не менять метаданные папки, поэтому старый размер остаётся снимком, а не гарантией актуальности.

Успешное повторное сканирование заменяет снимок только текущего корня. При ошибке или отмене его старый снимок и время удаляются, частичный результат не публикуется; кэш других корней сохраняется. Изменение общих исключений очищает весь кэш. После попытки очистки инвалидируются измерения затронутых объектов и их родительских каталогов, а также снимки, чьи корни находятся внутри затронутых папок; измерения соседних объектов и кэш остальных корней сохраняются. Это применяется и при ошибке или отмене, если попытка могла изменить файлы. Список перечитывается без глубокого анализа, отметки сбрасываются, автоматического сканирования нет. Время последнего успешного сканирования остаётся временем измерения, а не актуализации. Закрытие подтверждения без запуска ничего не сбрасывает. Снимки хранятся в приватной SQLite-базе схемы 1 `scan-cache.sqlite` рядом с конфигурацией. SQLite использует журнал `DELETE`, чтобы не оставлять постоянные WAL-файлы. Данные восстанавливаются после перезапуска только при совпадении метаданных корня и непосредственных объектов; их свежесть между запусками не гарантируется.

Текущий путь выделен цветом непосредственно над колонками списка; имена и пути показываются без внешних кавычек с сохранением экранирования управляющих символов. В шапке нет отдельной брендовой строки и нулевого счётчика `0 selected`. Компактная шапка сохраняет на виду отметки и предупреждение о скрытом выборе, а остальные сведения — сортировку, исключения, видимость, выбранный объём и время/полноту последнего анализа — размещает по доступному месту; в тесном окне выбор, оценка объёма, фильтр, диагностическое сообщение и глобальные исключения важнее необязательной сортировки и времени. Минимальный размер браузера — 32 × 12; даже с выбором, фильтром и сообщением остаётся полная запись. При ширине меньше 64 колонок запись занимает две строки, от 64 — одну. После завершённого сканирования при наличии сохранённого времени показывается `Last scan` с локальным временем последнего успешного измерения и количеством неизвестных/неполных элементов среди всех элементов текущего списка; исключённые и пропущенные не считаются. Статус включается в компактную шапку, если хватает места; на тесном экране вместо счётчиков может показываться `Incomplete`, полная строка доступна через `v` в подробностях. Для восстановленного снимка отдельная строка `Last scan HH:MM | Complete` в шапке опускается: время последнего успешного сканирования остаётся в красном предупреждении и в подробностях `v`. Время фиксируется только при успешном завершении сканирования, при возврате берётся исходное время снимка и не обновляется; повторный анализ заменяет его. Счётчики учитывают и элементы, скрытые фильтром или dot-переключателем. Сброс снимка сбрасывает и время. Это время измерения, а не проверки актуальности дерева. Нижние подсказки зависят от контекста и используют целые сочетания клавиш и действий; при тесном окне менее важные команды пропускаются. Прокручивается только область элементов. Детализация списка адаптируется к ширине окна; неизвестные и исключённые значения не получают полосы использования, частичные сохраняют отметку `Partial`. Длинные имена и пути сокращаются; `v` открывает прокручиваемые подробности с полными путями текущего каталога и элемента, а также полными сообщениями и полной датой/временем последнего сканирования. `Esc` возвращает к списку без изменения выбора.

Клавиша `.` в браузере показывает или скрывает файлы и каталоги, чьи имена начинаются с точки. По умолчанию они показаны; переключатель действует только на видимость и сохраняется в текущем запуске при навигации. Анализ продолжает учитывать скрытые файлы; отметки скрытых объектов сохраняются и явно учитываются при подтверждении очистки. В полях ввода точка вводится как символ.

Клавиша `/` открывает ввод фильтра по подстроке имени без учёта регистра. Фильтр действует только на текущий список, Enter возвращает к навигации с сохранением фильтра, Esc в списке или вводе фильтра сбрасывает его. Фильтрация сохраняет снимок и отметки; число отмеченных объектов, скрытых фильтром или переключателем dot-файлов, показано в закреплённой строке. Подтверждение очистки перечисляет все выбранные пути, включая скрытые фильтром, и отдельно предупреждает об их количестве. При отсутствии совпадений нельзя случайно открыть или отметить невидимый элемент. Успешный переход в другой каталог сбрасывает фильтр.

Нижняя область браузера состоит из двух строк. Первая показывает навигацию и `? help` и остаётся постоянной для данной ширины независимо от анализа и выбора. Вторая показывает доступные действия: сканирование до анализа, отметку и повторный анализ после него, предпросмотр и очистку при выборе. Команда очистки не теряется при наличии выбора. Поле фильтра вместо этих строк показывает `Enter apply | Esc clear` и подсказку ввода; `?` там вводится буквально и не обещается как справка. Если места мало, менее важные подсказки опускаются целиком, клавиши и их подписи не обрезаются многоточием. PgUp/PgDn перемещают курсор на фактическое число полных видимых записей с учётом текущей шапки, подвала и одной/двух строк на запись; Home/End работают по отфильтрованному видимому списку, не меняя отметок.

Текстовый индикатор `Lines` показывается только при переполнении реально прокручиваемых экранов: справки, подробностей, предпросмотра, подтверждения очистки, отчёта, подтверждения/результата AI-объяснения и ввода пути. Узкий общий экран может использовать `More`. Без переполнения строка индикатора освобождается, точное заполнение экрана не считается переполнением. У прогресса сканирования, ожидания предпросмотра/очистки, подтверждения сканирования и настроек индикатора нет; устаревшее смещение прокрутки не скрывает начало этих экранов. Браузер и редактор исключений используют отдельный счётчик `Rows`.

## Исключения и защита

Редактор исключений (`e`) показывает общий список масок и 16 предложений в одном списке с флажками: `node_modules`, `CloudStorage`, `.git`, `.venv`, `venv`, `__pycache__`, `.cache`, `Caches`, `.gradle`, `.next`, `.build`, `DerivedData`, `target`, `vendor`, `dist`, `build`. Описание выделенной маски закреплено над списком. `node_modules` позволяет пропустить установленные зависимости Node.js, `CloudStorage` — каталоги облачных провайдеров, в том числе вложенный `Library/CloudStorage`. `↑/↓` выбирают строку, Space или Enter включает или отключает маску. `a` либо Tab переводит фокус в поле `Add pattern`, Enter добавляет маску, Tab возвращает к списку. Повторное добавление уже включённой маски не отключает её. Неправильный ввод сохраняется для исправления. Отключённая пользовательская маска остаётся в списке до закрытия редактора. Esc закрывает редактор либо сначала отменяет ввод. Предложения не применяются автоматически. Изменения обновляют общий список и сбрасывают все сохранённые снимки анализа и отметки.

Общий список исключает совпадающие имена при сканировании любого выбранного каталога или диска, включая одноимённые файлы и каталоги на любой глубине. Совпавший каталог исключается вместе с поддеревом. Клавиша `E` (Shift+E) для выделенного файла или каталога в текущем списке добавляет или удаляет буквальную маску его имени; `x` делает то же только для каталога. Метасимволы имени экранируются; маска действует на потомков любых выбранных корней. Если объект исключён другой маской, например `*.tmp`, `E` предлагает изменить её через `e`, а не удаляет чужую маску. Через `e` маски можно вводить вручную, в том числе для вложенных имён, которых нет в текущем списке. Изменение в любом месте меняет общий сохранённый список. Локальных списков исключений, сохранённых переопределений и наследования нет. Одноразово включить исключённое содержимое можно только для отмеченной папки после отдельного подтверждения; общий список масок не меняется. При загрузке конфигурации прежний объект `masks` со списками по корням валидируется и преобразуется в один массив: корни сортируются, порядок масок внутри каждого списка сохраняется, точные дубли удаляются. Чтение не меняет файл; обычное сохранение записывает JSON-массив `masks`, включая `[]` для пустого списка. Пустые, `null` и отсутствующие маски читаются как пустой список; очищенный общий список после перезапуска не восстанавливает прежние правила. Совпадающие с масками потомки текущего корня нельзя очистить непосредственно. Если выбранная папка содержит защищённое поддерево, очистка блокируется. Если обычная очистка пропускает папку из-за исключённого потомка, приложение после выполнения остальных целей показывает отдельное подтверждение. По умолчанию выбрано `Leave folder untouched`; `Left` оставляет папку, `Right` или `Tab` выбирает `Retry entire folder (including excluded contents)`, `Enter` подтверждает только эту папку. Повтор использует тот же режим и исходную идентичность объекта; уже выполненные соседние цели не запускаются повторно. `Esc` оставляет все ожидающие папки нетронутыми и открывает отчёт. Разрешение действует только для этой операции, не записывается и не меняет глобальные исключения. Защищённые пути, проверка идентичности, границы тома и проверки целей символических ссылок остаются обязательными.

Граница текущей реализации: глобальность означает общий набор правил, а не запрет входа в пути. Маски проверяются только ниже выбранного корня; имя самого корня и его предков не проверяется. Поэтому прямой вход в каталог `cache` позволяет анализировать его детей даже при маске `cache`; при обнаружении того же каталога ниже другого корня он пропускается вместе с содержимым. Это ограничение масок имён не отменяет отдельную встроенную защиту системных объектов.

Анализ может показывать защищённые объекты, но удаление запрещено для:

- корня файловой системы, корней смонтированных томов и `~` как отдельных объектов; содержимое `~` доступно для ручного выбора, если не защищено другим правилом;
- корней домашних каталогов **других** пользователей вместе со всем их содержимым;
- системных поддеревьев `/System`, `/usr`, `/bin`, `/sbin`, `/dev`, `/private/etc`, `/private/var`, `/Library/Apple`, `/Library/Extensions`, `/Library/Keychains`, `/opt/homebrew`; ссылка `/var` на `/private/var` защищается по той же причине;
- предустановленных приложений под `/System/Applications`, а также `/Applications/Finder.app` и `/Applications/Safari.app`;
- структурных корней `/Applications`, `/Library`, `/Users`, `/Volumes`, `/private`, `/opt` как отдельных объектов;
- стандартных папок пользователя как целых объектов: `~/Desktop`, `~/Documents`, `~/Downloads`, `~/Library`, `~/Movies`, `~/Music`, `~/Pictures`; содержимое этих папок доступно для ручного выбора, если не защищено другим правилом;
- `~/.Trash`, `.Trashes` на внешних томах и каталога настроек самой утилиты вместе с их содержимым.

Защита проверяется по нормализованному пути и идентичности фактического объекта `(dev, ino)`. Нормализации и `EvalSymlinks` недостаточно: другое написание регистра или эквивалентное Unicode-имя на соответствующем томе не должно обходить запрет. Для правила «только объект» сравнивается идентичность кандидата с защищённым объектом; для правила «всё поддерево» проверяются также идентичности его предков. Те же проверки применяются к потомкам выбранной папки и к разрешённой цели символической ссылки без обхода её содержимого. Символическая ссылка с отсутствующей целью, с целью вне текущего корня анализа либо внутри исключённого поддерева блокирует действие для выбранного объекта и содержащей её папки. Принадлежность непосредственному родителю `ScanRoot` также проверяется по фактическим объектам. Нельзя просто приводить все пути к нижнему регистру: разные объекты на томе с учётом регистра должны оставаться различимыми.

Идентичности существующих защищённых корней фиксируются при инициализации защиты и сохраняются в течение сессии, в том числе при смене корня анализа. Перед действием реестр дополняется актуальными объектами по защищённым путям; ранее известный объект остаётся защищённым после переименования в этой сессии. Отсутствующий необязательный путь сохраняется как правило и проверяется повторно перед действием. Если метаданные, необходимые для проверки безопасности, недоступны, удаление блокируется с причиной. История переименований до запуска приложения не восстанавливается; ограничение неатомарности проверки и операции остаётся в силе.

Утилита не запрашивает `sudo` и не повышает права. При нехватке доступа она показывает неполный результат и понятную причину; при необходимости пользователь сам выдаёт терминалу разрешение Full Disk Access в настройках macOS.

## Исполнение и отказоустойчивость

При отметке через `Space` фиксируются путь и идентичность выбранного объекта `(dev, ino)`; ошибка фиксации не создаёт отметку. Снятие отметки удаляет эту запись. Предпросмотр (`p`) и экран подтверждения (`d`) используют сохранённые записи и не фиксируют объект заново. При открытии подтверждения создаётся неизменяемая копия списка и режима действия; `Enter` запускает её один раз. Для изменения списка или режима нужно закрыть подтверждение. `Esc` на экране подтверждения ничего не запускает и сохраняет текущий выбор.

Перед реальным действием каждый **отмеченный объект** проверяется повторно; если его путь исчез, стал указывать на другой объект, оказался защищённым или недоступным, операция для него пропускается с причиной. Для отмеченной папки подтверждение относится ко всему её содержимому **на момент операции**: новые обычные файлы внутри неё также перемещаются или удаляются. Если исключённый либо защищённый объект появился после предпросмотра, но до повторной проверки, операция для всей папки блокируется. Тестовый прогон поэтому показывает снимок текущего содержимого, а не гарантию неизменности списка до удаления. Операции по нескольким отмеченным объектам выполняются последовательно; результат показывается по каждому пути согласно разделу «Тексты интерфейса». Ошибка проверки или отмена до передачи объекта исполнителю, а также ошибка запуска системной команды означают пропуск без запуска действия. Вывод команды в отчёте ограничен 4 КиБ с отметкой об усечении. Ошибка исполнителя считается потенциально частичным выполнением: приложение не обещает, что файлы остались неизменны. Ошибка одного пути не мешает обработке остальных, кроме отмены всей операции. Окончательное удаление выполняет `/bin/rm -r -x -- <путь>` без shell и без `-f`; `-x` не даёт команде переходить на другой том. Проверка и вызов системной команды не атомарны: изменение дерева во время операции может обойти предварительную проверку. Никакого автоматического `sudo` или перехода от Корзины к окончательному удалению нет.

Во время очистки доступна только отмена через `Esc`; изменение настроек, навигация и повторный запуск заблокированы. Запрос отмены останавливает дальнейший запуск действий и отменяет текущую команду, если она уже работает. Ошибка прерванного исполнителя отображается как возможное частичное выполнение, ещё не запущенные объекты — как пропущенные. Интерфейс дожидается завершения исполнителя и показывает отчёт. Откат и полный перечень уже удалённых вложенных файлов в MVP не предусмотрены.

После попытки очистки, включая ошибку или отмену, размеры затронутых целевых объектов и их родительских каталогов становятся неизвестными; кэши подкаталогов затронутых папок удаляются. Снимки соседних объектов, не затронутых папок и независимых корней остаются. Текущий список перечитывается без глубокого анализа, выбор сбрасывается, отчёт по путям остаётся доступным. Новый подсчёт запускается только вручную. Закрытие подтверждения без запуска не считается попыткой очистки и не меняет выбор или кэш.

## Технический выбор

Язык — **Go** (решение пользователя). Полноэкранный интерфейс использует **Bubble Tea** для чтения клавиш и перерисовки и `charmbracelet/x/ansi` для учёта ширины и сокращения строк. Go управляет вызовами системных `/usr/bin/du`, `/bin/rm` и `/usr/bin/trash`, а также хранит настройки и проверяет защищённые пути. Для Корзины в первой версии используется системная `/usr/bin/trash`; если она недоступна, операция не выполняется и выводится ошибка. Целевая минимальная версия — **macOS 26**; её команды и сборка должны пройти проверку на macOS 26 до заявления о поддержке этой версии и завершённой сертификации стабильного выпуска. Опубликованный beta-релиз не закрывает эти проверки. Сборка отдельных бинарников для Apple Silicon и Intel; установка через Homebrew может быть добавлена позже.

Настройки хранятся локально в каталоге поддержки приложения пользователя. Просмотр файлов, локальный анализ и очистка не требуют сети и не отправляют данные. Дополнительное объяснение через Codex требует сети и после явного подтверждения передаёт Codex метаданные выбранного объекта; Codex также может читать содержимое файлов и отправлять его, в том числе за пределами выбранного пути, в рамках описанного выше доступа.

## Проверка результата

- Список текущего каталога и его путь появляются до глубокого сканирования. Вход в папку, возврат и ввод пути меняют корень без запуска `du`; переход сбрасывает отметки и фильтр, перечитывает непосредственный список и восстанавливает сохранённые размеры совпадающих элементов. Между сессиями эти снимки могут устареть; красное предупреждение показывает время последнего успешного сканирования и предлагает `s` для свежего анализа. Новые и заменённые элементы требуют сканирования. Ошибочный переход сохраняет прежнее состояние. `s` явно обновляет текущую папку; отменённое или неуспешное обновление удаляет её старый снимок и не публикует частичные данные. Предупреждение и предложение исключений появляются, когда исключений нет.
- Частичные и недоступные результаты не выдаются за точные. Совпавшие с масками потомки текущего корня и встроенно защищённые объекты нельзя удалить через выбранного родителя; маски не запрещают прямой вход в совпадающий корень, как описано в разделе исключений.
- Единицы результата `du` не зависят от унаследованного `BLOCKSIZE`: дочерний процесс всегда получает `BLOCKSIZE=512`.
- Альтернативный регистр и эквивалентные имена одного объекта не обходят защиту; отдельные объекты на томе с учётом регистра не смешиваются. Проверены правила «только объект» и «всё поддерево», включая переименование известного защищённого объекта в сессии.
- Тестовый прогон не меняет файлы. Корзина и окончательное удаление действуют только на подтверждённые вручную объекты; неуспех Корзины не вызывает окончательное удаление.
- Интерфейс на английском; подписи размера и результаты соответствуют разделу «Тексты интерфейса». Результат операции не заявляет измеренное освобождение места на основании старой оценки.
- Выбор фиксируется при отметке; подмена объекта между отметкой и подтверждением обнаруживается и без тестового прогона.
- Пропуск до запуска отличается от ошибки исполнителя с возможными изменениями. После попытки очистки оценки затронутых объектов и родительских каталогов недействительны; несвязанные соседние размеры сохраняются. Новый анализ требует команды пользователя.
- Результаты размеров сохраняются в приватной SQLite-базе схемы 1 `scan-cache.sqlite` рядом с настройками. При запуске они восстанавливаются только после проверки идентичности и метаданных корня и непосредственных элементов; вложенные изменения могут остаться незамеченными, поэтому восстановленные размеры могут быть устаревшими. Глобальное изменение исключений удаляет все сохранённые результаты. Попытка очистки инвалидирует только затронутые цели и их предков и удаляет снимки, корни которых находятся внутри затронутых папок; независимые размеры сохраняются. Неудачный или отменённый анализ удаляет запись только текущего корня.
- Рядом с базой используется приватный advisory-lock-файл `scan-cache.sqlite.lock`. Операции кэша берут общий lock с ограниченным ожиданием 250 мс. Очистка получает эксклюзивный lock перед сохранением инвалидации и удерживает его до завершения исполнителя и итогового обновления списка. Пока он удерживается, другие экземпляры приложения не могут читать или записывать кэш; если эксклюзивный lock получить не удалось, очистка не начинается. При завершении или сбое процесса ОС освобождает lock.

## Принятые решения

- Список текущего каталога вместо раскрываемого дерева; вход в папку сразу меняет корень анализа, подсчёт запускается отдельно.
- Bubble Tea вместо собственного терминального движка; `os.ReadDir` как безопасный эквивалент `ls`, системные `du` и `rm` для подсчёта и окончательного удаления.
- macOS 26+ и `/usr/bin/trash` для первой версии, с незавершённой проверкой совместимости на macOS 26 до заявления о поддержке и стабильной сертификации.
- Корзина по умолчанию; обязательное подтверждение перед реальным действием.
- Скрытые файлы видны; символьные ссылки не обходятся; другой том сканируется только как выбранный корень.
- Защищённое поддерево всегда блокирует выбранную папку; исключённое поддерево по умолчанию пропускает её и требует отдельного явного подтверждения на включение только для этой операции.
- Подтверждение удаления папки охватывает новые обычные файлы внутри неё; замена самой отмеченной папки по тому же пути не охватывается подтверждением (решение пользователя).
- Кэш результатов сканирования сохраняется между сессиями в каталоге поддержки приложения. Нет телеметрии и автоматического повышения прав.
