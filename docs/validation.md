# Validation status

The MVP is implemented. The [current design specification](design.md) is the behavior authority; the deferred tree-navigation document is not part of this release. A prerelease has been published; it does not certify all target platforms or close the release gates below.

## Current behavior and verification update — 2026-10-30

This section records evidence for the source checkout after the later audit fixes. Earlier stages and test counts are preserved separately in the [historical validation snapshots](archive/2026-10-30-validation.md). Published prerelease evidence is distinguished below; recorded checks do not replace the remaining release gates.

- **Global exclusions:** one list applies to every selected folder or disk; patterns match names at any depth. Existing root-keyed configuration is merged without exact duplicates during load, not written until the next save, then stored as the global list. `E` toggles a literal-name exclusion globally; `e` edits the shared list. Regression coverage: `internal/config/settings_test.go`, `internal/ui/state/global_exclusions_test.go`, and `internal/ui/state/quick_exclude_test.go`.
- **Scanning and cancellation:** a stale browser notification clears when scan confirmation opens; newly produced errors and cancellation messages remain visible. Cancellation is checked for empty scans and through final result application. A vanished immediate entry is skipped only for `ENOENT`; other metadata errors fail the scan. Delayed scan/preview success events are discarded after cancellation, while completed cleanup reports remain available. Regression coverage: `internal/scan/progress_test.go`, `internal/scan/list_test.go`, `internal/ui/state/scan_message_test.go`, and `internal/ui/state/review_regressions_test.go` (including delayed scan/preview delivery and cleanup-report retention).
- **Session-only size cache:** completed scans are retained in memory by canonical root until exit. The worker captures immediate root/entry identity and metadata before measuring; results are validated against that evidence before application. A replaced root rejects the result; changed/replaced entries stay unknown and make the snapshot partial. Returning refreshes the immediate listing and restores measurements only when root and entry identities/metadata still match. Nested changes can escape immediate-entry checks. Navigation restores the prior cursor path where possible (including highlighting the child when returning to its parent), while clearing selection and filter. A failed/cancelled rescan evicts that root's prior snapshot and never publishes partial results. Global-mask edits and any cleanup attempt clear all saved scans. The cache is not written to configuration or disk. Regression coverage: `scan_cache_test.go`, `scan_observation_test.go`, and `navigation_history_test.go`.
- **Last scan status:** after a successful scan with a timestamp, the compact header can show local time and unknown/partial counts over all current immediate entries; excluded and skipped entries are omitted. The full date/time and counts remain in `v` details. Regression coverage: `scan_time_test.go` and `scan_status_test.go`.
- **Terminal wrapping and scroll indicators:** text wraps to terminal-cell width without splitting combining or joined Unicode graphemes. `Lines`/`More` appears only on scrollable screens when content overflows; scanning, previewing, cleaning, scan confirmation, and settings do not show them. If the viewport cannot fit both a scroll indicator and a content line, it shows `Resize`. Regression coverage: `review_regressions_test.go`, `help_indicator_test.go`, and `scroll_indicator_test.go`.
- **Cleanup reports:** a runner error returned before the system command starts (cancellation after the final check, or a failed process start) is reported as `Skipped`, not as a possible partial change. Captured `trash`/`rm` output is limited to 4 KiB per item and marked when truncated. Regression coverage: `TestRunnerNotStartedIsReportedAsSkipped` and `TestRunBoundsReportedCommandOutput` in `internal/cleanup/cleanup_test.go`.
- **AI CLI failure handling:** verbose stderr is truncated for classification instead of cancelling a valid answer; the request time limit returns a classified message; a successful CLI exit whose background child keeps stdout open still returns the completed answer; HTTP `401`/`429` are matched only as whole numbers. Regression coverage: fake-CLI tests in `internal/explain/cli_test.go`.
- **Compact browser and navigation:** the header adapts to available space; contextual footer hints keep whole key/action tokens and omit lower-priority commands when crowded. `PgUp/PgDn` move by the actual visible viewport; `Home/End` go to the first/last visible item, respecting filters and hidden-file visibility without changing selection or scan state. Pressing `t` explicitly resets the cursor to the first visible item while preserving selections and the scan snapshot; automatic sorting retains cursor-history behavior. Regression coverage: `browser_compact_test.go`, `browser_navigation_test.go`, and `sort_test.go`.
- **Path entry:** `r` opens an empty field for an absolute, `~`/`~/`, or current-folder-relative directory path; `r path` remains visible at widths 32, 40, 64, 80, and 120. Paste or type then press Enter. Matching outer quotes and one copied CRLF newline are handled; spaces and Unicode are accepted, while literal quote/space names remain addressable. Ctrl+U clears only the path field. Typing and invalid, multiline, missing or non-directory input preserve browser state. Successfully opening a directory clears selection and the name filter, like normal navigation; global exclusions remain unchanged. Opening a pasted directory does not scan it. Regression coverage: `TestRootInputPastesCopiedPathsWithoutAppendingCurrentFolder` and `TestInvalidRootInputPreservesCurrentBrowserState` in `path_input_test.go`, `browser_compact_test.go`, and the Bubble Tea adapter paste test in `internal/ui/model_test.go`.
- **AI Explain:** the UI flow is `i` on the highlighted item → explicit read-access confirmation → choose `Answer language: English` (default) or `Русский` → Enter to run the installed, authorized Codex CLI (`codex exec`) with read-only command permissions → scrollable informational result. The choice is saved immediately as `explain_language` (`en`/`ru`); it changes only the answer language, while instructions remain in English and no filesystem metadata is added. Config tests cover English defaults for new and legacy settings, round-trip persistence and rejection of invalid values. State tests cover Left/Right/Tab switching, immediate save, language capture at confirmation, unchanged browser state and save failure. Prompt tests verify that the answer language appears at the start and end of the English instructions, only those directives change, and the metadata payload stays the same. The prompt requests a fixed plain-text format, defines the risk scale and bounds read-only inspection to quick metadata commands. Metadata tests cover the last scan result (`null` when unscanned, validated states), deletion mode, ownership, symlink target text without following the link, child kinds, and a bounded child count; a UI test checks that the request carries the browser's cached measurement and exclusion reason. Answer quality with a live model has not been evaluated. The confirmation discloses that Codex may read file contents and files beyond the selected path and send information to Codex; no separate API key is required for an authorized CLI. Read-only command permissions do not guarantee complete isolation from every Codex capability. DiskCleaner does not change selection or start cleanup. Confirmation and results show `Lines` on overflow; the working screen does not. Esc backs out or cancels and waits for active work before returning; errors show diagnostics. Fake-CLI tests cover the invocation contract, output limits/protocol, error classes, timeout, cancellation and child-process cleanup. Metadata regression coverage checks logical and allocated values against filesystem blocks, sparse and empty files, known-zero versus unavailable (`null`) allocation, and directory-entry sizes without recursive totals; the targeted tests and full `internal/explain` suite passed. An offline CLI argument/config parsing probe used a synthetic `CODEX_HOME` and intentionally invalid provider; it made no model request and did not test version detection. No live Codex request was run.

## Recorded source-checkout verification

AI Explain PTY smoke checks passed at 80×24 and 32×12 with a fake CLI: confirmation, Enter, scrolling to the result end, Esc back, and quit. At 80×24, a slow fake request was also cancelled with Esc and returned to the browser before quit. Fixtures were disposable and removed; checks used no user file contents, made no model requests, ran no cleanup, and changed no settings.

Current host: macOS 27.0.1, Apple Silicon (`arm64`), Go 1.27.3; the module minimum remains Go 1.26. Current automated evidence after the scan-cancellation, scan-observation/cache, UI regression, cleanup-report and AI CLI failure-handling fixes: `go test -race ./...`, `go vet ./...`, native `go build -o diskcleaner ./cmd/diskcleaner`, and `git diff --check` all passed. The earlier release-packaging checks are recorded separately above; they do not establish that the published binaries include the later source fixes. This does not certify macOS 26, native Intel runtime behavior, or a successful system Trash move.

**Current limitations:** exclusion matching is scoped below the selected scan root; opening an excluded-name folder directly makes it the root, so that root name itself is not excluded. Masks match exact characters and case, like `du -I`, so differently normalized Unicode spellings of a name are not treated as equal. Any symbolic link inside a selected folder whose target is missing or outside the scan root blocks that folder, which fails closed but can block common targets such as virtual environments. Session-cache validation compares each immediate entry's identity and metadata; changes deeper inside an otherwise unchanged directory may go undetected. `Last scan` reports the latest completed measurement, not real-time filesystem state. See [user guide: exclusion scope](usage.md#global-exclusions-and-size-estimates) for the exclusion boundary and [user guide: session scan behavior](usage.md#browsing-and-paths) for cache semantics.

PTY smoke checks used 45 disposable files at 80×24 and 32×12. They covered the compact header, Page Down/End/Home, scan and timestamp display, selected state, and complete footer command tokens. These checks performed no cleanup and made no saved-exclusion edits. An earlier terminal walkthrough also checked returning from a child to its parent with cached sizes and using the global exclusions while starting outside the home directory.
